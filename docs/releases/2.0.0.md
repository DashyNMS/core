DashyNMS Core 2.0 reads LibreNMS 26.10 and 26.11, and holds everything DashyNMS Desktop, Mobile and MCP share: alerting, sensors, search, Intelligence and settings.

## Breaking

- **Alerts are read as LibreNMS 26.10 faults**, through `/faults`, with older servers still supported. Implementations of `IAlertsApi` add `GetSourceAsync`, and lists on 26.10 hold a row for each fault (#15).
- **`Sensor.Current` is `double?`**, so a missing or non-finite reading isn't a number. Use `HasReading`, and show a dash rather than zero (#42).
- **`IntelligenceDetail` replaces `IntelligenceReplyStyles`**, and the `replyStyle` parameters are now `detail`. Saved choices carry over (#40).
- **`AskAsync` takes Spotlight as `IntelligenceObjectReference`s** instead of a description, so network names never reach the instructions. Pass each object's `Identity` (#89).
- **`IDeviceCache.LastRefreshed` has no default.** Other implementations say when they last refreshed (#34).

## New

- **Update channels:** Stable, Nightly and Edge, with how their builds rank and when one is an update (#104).
- **Network Search:** find an endpoint by address, network, MAC or name, with the switch ports, routers, subnet and conflicts around it (#91).
- **Independent sensor definitions:** state names and colours update separately from the apps, matched with device context, and keep working offline (#52, #57, #58).
- **Fault grouping** by device and rule, rolled up by rule (#16).
- **Unknown stays unknown:** device readings a server leaves out are reported as unknown instead of zero or false (#72).
- **Request limits:** hosts can cap how many requests are in flight (#99).
- **Busy logs:** event and alert log reads can continue back from a time (#101).
- **Request measurements:** hosts can observe how long requests take, with nothing about the network in them (#68).
- **Intelligence:** typed objects, including one interface, stay in a chat's context and evidence (#46, #50), and every route shares its instructions, tool running, provider choices and personality (#98).
- **Sign-in links** can be written and read as the QR code Desktop shows (#74).
- **Event log and Graylog cards** can keep to a Spotlight (#77), and device logos are cached on disk (#79).
- **Settings** for diagnostics sharing, automatic downloads, single chat and the Ports layout (#60, #62, #64, #66, #83), and a save that says whether it reached the disk (#85).
- **Update packages** are verified for each desktop platform (#44).
- **Resource APIs** work over any transport, for other hosts' tests (#25).

## Changed

- **Packages:** every commit to `main` is published as `2.0.0-edge.N` and each night's changes as `2.0.0-nightly.N`, with build provenance (#103). They rank above `2.0.0-ci.N`.
- **Monitors, caches and the dashboard layout** moved here from Desktop (#13).

## Fixed

- **LibreNMS 26.11:** VLAN numbers and rule fields (#86, #87). **26.10:** device fields, fault polls counted as alert requests, and permissions for each resource (#21, #22, #75).
- **Alerting:** fault details and history by `fault_id`, acknowledging with the scope LibreNMS applies, recovery for faults, and single-fault results without untouched siblings (#17, #18, #19, #70).
- **Rules:** settings for each entity and a field catalogue that follows the server's version (#20).
- **Sensors:** slow lists load without repeated timeouts (#41), and corrected catalogue versions are accepted (#55).
- **Graphs:** legend readings that are unavailable are told apart from zero (#80).
- **Intelligence:** a single fault keeps its source (#48), status cards show ignored and unreported devices (#94) and understand alert groups (#28), a question needing many lookups still gets an answer (#38), one damaged chat doesn't stop the others loading (#30), and web search waits for consent to the notice that describes it (#32).
